# المرحلة 10 — الجزء C: إعدادات live ومفتاح الطوارئ

التاريخ: 6 أكتوبر 2026. النسخة 1. **C مكتمل محلياً في الإعداد والتوثيق والتحقق؛ لم تُغيّر إعدادات الإنتاج ولم يُفعّل البيع الحقيقي بهذا العمل.** التالي D بعد توجيه المالكة.

## 1. التفويض والقرارات

قالت المالكة «ابدا المرحلة التالية» بعد B، فتُنفّذ C وحده. أجابت عن قراري الأعلام: **الاسترداد يبقى مطفأً مؤقتاً**؛ **الأستاذ يُفعّل آلياً للطلب الحقيقي في E**. لا يُسأل عنهما مجدداً ولا يتغيران لمجرد تركيب `sk_live_`. إعفاء G3 محفوظ؛ التجارب غير المنفّذة لا تُكتب PASS. موانع G6 وغيرها باقية في قائمة الجاهزية.

لا تغيير لملفات التطبيق أو SQL أو الهجرات؛ الحراس القائمة تحقق المطلوب. لا تعديل Vercel أو أسرار أو تشغيل job حي أو شراء/رد/فاتورة حقيقية، ولا commit أو نشر أو تغيير ذاكرة دائمة.

أداة مسارات Next تستعمل NextRequest/NextResponse وحماية Origin/Host الفعلية ورموزاً مصطنعة، وتمنع fetch الخارجي؛ handlers حقيقية لكن المعالجات المالية وSupabase/Auth والأستاذ بدائل تسجيل. ليست اختبار HTTP لنشر Next أو إثبات مصادقة Supabase حقيقية. أدوات PostgreSQL الأخرى تستعمل **المعالجات والهجرات الحقيقية** مع محاكي محلي؛ لا تختبر البنك أو فاتورة أستاذ حقيقية. الخوادم المؤقتة أُغلقت في نهاية كل أداة.

كانت أول محاولة أداة Next تعطي 403 لغياب Host في fixture، فصُحح الطلب المصطنع ليطابق عقد حماية المصدر. لم يُضعف حارس التطبيق ولم يُعامل ذلك كخلل إنتاج.

لم يُعد تشغيل TSC/ESLint على التطبيق في C لأنه لم يتغير؛ آخر مقارنة في B كانت **38 → 38، دون تشخيص جديد** وESLint نظيف للملفات الثمانية. هذه نتيجة B السابقة وليست ادعاء فحص C جديد. لا قبول بصري/جهاز/جلسة دفع حقيقية في C.

## 6. ما يراجعه المراجع والتراجع

راجع Production-only والقيم المستقلة وقرار الرد false/الأستاذ true في E؛ وأن إذن live وسر ميسر لا يُطفآن عند الطوارئ؛ وأن نشر المتغيرات وروابط الدفع القديمة موثقان. راجع الفرق بين ربط المسارات ببدائل التسجيل واختبار المعالجات على PostgreSQL محلي، وبينها جميعاً والقبول الحقيقي المؤجل.

التراجع المحلي عن C: حذف ملفات C الثلاثة الجديدة فقط (LIVE-CONFIG/RUNBOOK/أداة switch) وحذف هذا التقرير عند رفضه، وردّ أسطر حالة C فقط في الملفات القائمة وإعادة سطر اختبار refunds السابق عند الحاجة. لا reset عام، لا تغيير B أو أي عمل متزامن، ولا SQL/مال/نشر يحتاج تراجعاً. إبقاء الحالة الأقوى في اختبار refunds لا يغير التطبيق.

التالي D للتحقق الرسمي من Apple Pay في الفاتورة المستضافة ومتطلباته؛ E للإعداد/الطلب الحقيقي بيد المالكة بعد الجاهزية. الاسترداد الحقيقي في E مؤجل بقرار الرد المطفي، لذلك لا يُعلن معيار E أو الإطلاق النهائي مكتملين. F يستكمل RUNBOOK وجميع أحكام القائمة. لا فتح عام تلقائياً.
