# إعدادات إطلاق ميسر live — الجزء C

6 أكتوبر 2026. هذا **جدول تنفيذ لاحق للمالكة في الجزء E**، وليس إثباتاً أن القيم ضُبطت. لا تغيير للبيئة أو أسرار أو نشر في C. الاسترداد يبقى مطفأً مؤقتاً بقرار المالكة، وإرسال الأستاذ الآلي يُفعّل للطلب الحقيقي في E. شروط الأمن والقبول الباقية في [قائمة الجاهزية](LAUNCH-CHECKLIST.md).

## 1. القيم غير السرية — Production فقط

المشروع `yasmin-alsham-new2`. تختار المالكة Production في إعدادات Environment Variables. لا تُضاف مفاتيح live إلى Preview أو Development. القيم التالية حزمة الجزء E بعد التحقق من D والجاهزية؛ فتح المتجر للعموم يحتاج التوجيه الصريح المقرر بعد E.

لا يُعد ضبط طلبات الإدارة في Preview ضبطاً لـProduction. إبقاء checkout مفتوحاً عند الطوارئ يسمح بإنشاء طلب غير مدفوع؛ إذا أرادت المالكة وقف إنشاء الطلب أيضاً فذلك قرار مستقل، وليس ضرورياً لإيقاف الدفع الجديد.

## 2. الأسرار والاعتماديات — لا قيم سرية في هذا الملف

| الاسم | المطلوب في Production |
|---|---|
| `MOYASAR_SECRET_KEY` | المفتاح السري للحساب **live**، يبدأ `sk_live_`؛ تضعه المالكة مباشرة في Vercel كـSensitive. لا مفتاح publishable مكانه |
| `MOYASAR_WEBHOOK_SECRET` | سر جديد للـwebhook live، 16 حرفاً على الأقل؛ يطابق لوحة ميسر حرفياً، وتضعه المالكة كـSensitive |
| `SUPABASE_SERVICE_ROLE_KEY` | الحفاظ على مفتاح خدمة المشروع القائم؛ خاص بالخادم ولا يُنسخ إلى أي `NEXT_PUBLIC_*` |
| `NEXT_PUBLIC_SUPABASE_URL` | عنوان مشروع Supabase القائم `qbbijtyrikhybgszzbjz`؛ لا تبديل مشروع |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | المفتاح العام الحالي للمشروع؛ يستخدم للتحقق من جلسة الموظف، وليس service role |
| `FABRIC_STORE_ACCESS_SECRET` | السر القائم، 32 حرفاً على الأقل. لا يُدوّر ضمن الإطلاق/الطوارئ كي تبقى رموز الوصول والتتبع صالحة |
| `CRON_SECRET` | السر القائم، 16 حرفاً على الأقل؛ ترسله Vercel في Authorization للجدولة. لا نشره أو إدخاله في URL |
| `ALOSTAZ_API_TOKEN` | توكن حساب الأستاذ المعتمد القائم، خاص بالخادم؛ مطلوب عند تفعيل الإرسال |

لا يحتاج مسار Invoices API الحالي إلى `NEXT_PUBLIC_MOYASAR_*`. لا تضف مفتاحاً عاماً أو تكامل بطاقة في المتجر ضمن C.

إعدادات أخرى يجب الحفاظ عليها:

- `MOYASAR_API_BASE`: اتركه محذوفاً لاستعمال `https://api.moyasar.com/v1`؛ العنوان الرسمي نفسه مقبول إن كان مضبوطاً. أي عنوان محاكي مرفوض على Production/live.
- `ALOSTAZ_BASE_URL` و`ALOSTAZ_FABRICS_VAT_TAX_ID`: احفظ الإعداد المعتمد إن كان موجوداً، ولا تخترع tax ID. الافتراضي من `alostaz-config.ts` للحساب الحالي، وضريبة القماش تُحل حسب الإعداد/خدمة الأستاذ القائمة. إعدادات منتجات القياس والمشغل النسائي لا تتغير بهذا الإطلاق.
- `VERCEL_ENV` و`NODE_ENV`: تديرهما المنصة/البناء؛ لا تضبط قيمة Preview لإخفاء حارس test على Production.
- `CAPACITOR_BUILD`: محذوف أو `false` في نشر الموقع؛ نسخة static للـAndroid ليست نشر API المتجر.
- `vercel.json`: الجدولة الحالية `/api/fabric-store/jobs/run/` كل خمس دقائق (`*/5 * * * *`)؛ لا تعديل عليها في C. وجود الجدول لا يثبت نجاح التشغيل الفعلي.

## 3. webhook live

في لوحة ميسر **live**، تضبط المالكة عنوان POST:

`https://www.yasmin-alsham.fashion/api/payments/moyasar/webhook/`

تُحفظ الشرطة الختامية، وسر جديد يطابق `MOYASAR_WEBHOOK_SECRET` في الحزمة نفسها. لا يكفي إعداد webhook test السابق. الأحداث المعالجة: `payment_paid` و`payment_faild` (بهذا الهجاء الرسمي) و`payment_refunded`. يطابق المعالج `secret_token` داخل الجسم وبيئة `live`، ثم يجلب الدفعة من ميسر للتحقق؛ ليس هناك ترويسة HMAC جديدة مطلوب اختراعها. [مرجع ميسر الرسمي](https://docs.moyasar.com/api/other/webhooks/webhook-reference).

تنسّق المالكة تبديل مفتاح ميسر وسر/إعداد webhook وإذن live وإزالة إذن test في E؛ لا تُبدّل أحدها وحده أثناء C. تُراجع المحاولات السابقة غير المنتهية قبل تبديل البيئة: مفتاح live لا يثبت حالات دفعات test. لا تصنّف محاولة test على أنها live، ولا تمحو السجل السابق.

## 4. ما تحققنا منه حالياً قراءةً

أسماء المتغيرات ونطاقها ونوع تخزينها فقط، **لا قيمها ولا نوع مفتاح ميسر**:

| مجموعة | Metadata Vercel في C |
|---|---|
| أسرار ميسر، CRON، access، service role | موجودة في Production؛ ميسر/CRON/access Sensitive |
| checkout خادم/واجهة | موجودان في Production؛ قيمة التشغيل لم تُقرأ |
| orders خادم/واجهة | موجودان في **Preview فقط**؛ يلزم إضافتهما لـProduction عند E |
| Payments / Refunds / Reconcile / Alostaz flag / live permission / test permission | غير مدرجة في الجرد؛ لا يُستنتج منها تشغيل live. defaults false/رفض كما في الكود |
| Supabase URL/anon | موجودان للبيئات الثلاث |
| توكن الأستاذ | موجود لـProduction وPreview؛ لا إثبات لصلاحيته أو إرسال فعلي |

## 5. تطبيق لاحق والحدود

حفظ متغيرات Vercel لا يغيّر نشر الإنتاج القديم؛ يلزم نشر جديد ثم READY وربط النطاق للإعداد الجديد وفق [توثيق Vercel](https://vercel.com/docs/environment-variables/managing-environment-variables). في E تُراجع المالكة الحزمة، ثم يُتحقق من أول طلب قراءةً دون كشف أسرار. لا تستدعي jobs يدوياً لمجرد فحص HTTP: GET المحمي يشغّل آثاراً مالية ومحو عناوين مؤهلة.

تشغيل الأستاذ قد يعالج أيضاً مهام الفواتير الحقيقية المستحقة في الطابور؛ تُراجع المهام قبل تفعيله في E. لا إعادة إرسال لفاتورة تاريخية أو معلومة النتيجة دون تحقق من مرجعها. الاسترداد الحقيقي المطلوب في معيار E **غير منفّذ ومؤجل** ما دام مفتاح الرد مطفأً؛ لا يُكتب PASS أو يُفعّل تلقائياً لتجاوز هذا القرار.

خطوات الطوارئ في [RUNBOOK.md](RUNBOOK.md). دليل الاختبارات وحدودها في [تقرير C](stage-10-c-live-config-and-emergency-switch.md).
