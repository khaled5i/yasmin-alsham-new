## 2. التصميم

### 2.1 الاسترداد على مرحلتين حول نداء ميسر
ميسر **بلا مفتاح عدم تكرار للاسترداد** (التوثيق الرسمي، `POST /payments/:id/refund` بـ`amount` اختياري). ردّ ضائع + إعادة نداء = المبلغ مرتين. لذلك:

1. `fabric_store_refund_begin` (تحت قفل الطلب): يسجّل الاسترداد `pending` مع `provider_refunded_before` (ما سجّلناه مسترداً قبله) وحجزاً دقيقتين. **استرداد معلّق واحد للطلب** (فحص في الدالة + فهرس فريد). مفتاح الضغطة من المتصفح (`idempotency_key`) يعيد نتيجة الاسترداد نفسه.
2. `settleRefund` (TypeScript): يجلب الدفعة من ميسر أولاً:
   - نداء سابق مسجّل و`refunded ≥ قبل + المبلغ` ⇒ نجح ورده ضاع: يُسجَّل **بلا نداء**.
   - `refunded = قبل` ⇒ `fabric_store_refund_mark_called` (لحامل الحجز فقط) **ثم** نداء واحد.
   - غير ذلك ⇒ استرداد لم نسجّله: `mismatch`، بلا نداء، والطلب يُرفع للمراجعة ويُبلَّغ الموظف.
   - رفض 4xx ⇒ `failed`. انقطاع أو 5xx أو مهلة ⇒ يبقى `pending`.
3. `fabric_store_due_refunds` (المهمة المجدولة كل 5 دقائق): المعلّق الذي انتهى حجزه ⇒ الخطوة 2 نفسها.
4. `fabric_store_refund_finish` (تحت قفل الطلب ثم الاسترداد): `succeeded` يُقبل فقط إن أظهر ميسر `قبل + المبلغ` على الأقل (أكثر ⇒ يُقبل ويُراجع). ثم: حالة الدفع `partially_refunded`/`refunded`، وصف المرتجع، والإلغاء وإعادة المخزون إن كان إلغاءً.
5. **مفتاح test لا يرد دفعة live** ولا العكس: يبقى معلّقاً حتى يعمل المفتاح الصحيح.

### 2.2 قواعد البدء
| الحالة | النتيجة |
|---|---|
| قبل القص + كل الباقي | **إلغاء** فقط (`use_cancel` إن لم يُطلب إلغاء): يُلغى الطلب ويعود القماش |
| قبل القص + جزء | مسموح (مثلاً رسوم شحن) |
| إلغاء بعد القص | `already_cut` |
| إلغاء بمبلغ أقل من الباقي | `bad_request` |
| سداد live بلا مبيعة مسجّلة | الإلغاء فقط؛ الجزئي `sale_pending` (الاعتماد لا يبيع ما استُرد جزئياً) |
| أكثر من الباقي | `exceeds` (وحارس المرحلة 2 طبقة ثانية) |
| «بدء التجهيز» أثناء إلغاء معلّق | `refund_pending` (تعديل `set_fulfillment`) |

### 2.3 الواردات: صف مرتجع سالب
`category = 'fabric_store_refund'`، `amount` سالب، `payment_method = 'network'`، مصدر «المتجر الإلكتروني»، `is_automatic`، رقم فاتورة **جديد** من تسلسل الأقمشة (الفهرس الفريد على `invoice_number` لفرع الأقمشة يمنع إعادة رقم المبيعة، وtrigger الترقيم يفشل داخل `search_path=''` — درس 20)، والوصف «مرتجع عن الفاتورة N». **المبيعة الأصلية لا تُمس.** الصف مقفل (تعديل `protect_online_sale`). لدفعة test ولسداد بلا مبيعة: لا صف.

### 2.4 المخزون
- **الإلغاء قبل القص** (مبيعة live مسجّلة): حركة IN لكل سطر بكامل ما خُصم، باسم المدير.
- **بعد القص/التسليم**: `fabric_store_restock_return` بالطول الصالح لكل سطر، وملاحظة فحص إلزامية، ومفتاح طلب. المجموع لكل سطر ≤ ما خُصم له.
- الحركات **بلا `sale_income_id`** عمداً: trigger المحل يحذف حركات المبيعة عند تعديلها.
- كل إعادة في `fabric_store_restocks` (سجل للقراءة فقط لـservice_role؛ الكتابة بالدالة وحدها).

### 2.5 الأستاذ
- **لا فاتورة** لصف المرتجع، ولا لمبيعة طلب استُرد كاملاً قبل إرسالها (المبيعة والمرتجع يتقابلان في الواردات).
- الإشعار الدائن **يدوياً**: اللوحة تعرض «مطلوب إشعار دائن» حين يكون للمرتجع صف وفاتورة البيع وصلت الأستاذ، ويُكتب رقمه (`fabric_store_record_credit_note`، مرة واحدة). مبيعة استُرد جزء منها قبل إرسال فاتورتها: الفاتورة تُرسل كاملة، واللوحة تنبّه أن إشعاراً سيلزم.

### 2.6 webhook «refunded»
كانت المرحلة 5 تحجر **كل** دفعة حالتها `refunded`. الآن: إن كان `refunded` لدى ميسر ≤ ما سجّلناه (معلّق + ناجح) ⇒ `ignored`؛ غير ذلك يُحجر كما كان.
