## 2. التصميم

### 2.1 من يستطيع
- **الخادم يقرر:** كل مسار موظف يتحقق من رمز الجلسة عند Supabase Auth ثم يقرأ الدور بعميل الخدمة (نفس نمط «إرسال للمحاسبة»). المحاسب والمدير العام **لا** يصلون (قرار المالك)، ولو كانت لهم صلاحية المحاسبة.
- **القاعدة تسجّل:** الدوال لـ`service_role` وحده؛ تأخذ معرّف الموظف وتضبط `fabric_store.actor_type='staff'` و`actor_id`، فيكتب trigger المرحلة 2 كل انتقال باسمه. حارس المرحلة 2 يبقى الحكم على الانتقالات: لا تجهيز لطلب غير مدفوع أو تحت المراجعة، ولا «شُحن» لطلب استلام، ولا عودة من «شُحن».
- **الواجهة:** البطاقة والصفحة تُخفى عن غيرهما؛ والإخفاء ليس الحماية (المسار يرد 403).

### 2.2 تغيير الحالة — `fabric_store_staff_set_fulfillment`
| الطلب | النتيجة |
|---|---|
| هدف غير معروف، أو ملاحظة > 500 | `bad_request` |
| نفس الحالة الحالية | `ok` بلا تغيير (الضغط مرتين لا يكتب حدثين) |
| تقدّم لسداد **live** بلا مبيعة في `income` | `sale_pending` — القماش لم يُخصم بعد (المرحلة 6)؛ دفعة test مستثناة لأنها لا تبيع |
| إلغاء طلب **مدفوع** | `refund_required` — الإلغاء مع استرداد = المرحلة 8، للمدير |
| إلغاء طلب غير مدفوع | يُلغى ويُحرَّر حجزه فوراً (`fabric_store_release_order_reservations`) |
| «شُحن» بلا شركة أو بلا رقم بوليصة صالح (`[A-Z0-9-]{3,60}` بعد حذف المسافات وتكبير الحروف) | `tracking_required` |
| ما يرفضه الحارس أو قيد | `refused` + الكود، ولا أثر (كتلة فرعية) |
| ملاحظة | تُضاف للسجل باسم الموظف |

### 2.3 حسم المراجعة — `fabric_store_staff_resolve_review`
ملاحظة إلزامية (3–500). ترفع العلامة (السبب محفوظ في السجل منذ رُفعت)، وتضيف «حُسمت المراجعة: …» باسم الموظف، وتُغلق تنبيهات `notify_staff` المفتوحة للطلب. **لا تسجّل مبيعة ولا ترد مالاً**: طلب live بلا مبيعة يبقى `sale_pending`.

**النسخة 2 (`20260929170000`):** الحسم يشترط لقطة ما عرضته الشاشة، وإلا `review_changed`. ولطلب live مدفوع غير ملغى بلا مبيعة يعيد جدولة `confirm_order` (`confirmation_queued: true`)، فتُسجَّل المبيعة في التشغيل التالي للمهمة إن توفّر القماش.

### 2.4 تتبّع الزبونة
- الرابط `/fabrics/order/?t=<رمز>`؛ الصفحة ترسل الرمز في ترويسة `x-order-token` (لا في عنوان المسار، فلا يظهر في سجلات الخادم). بلا رمز: كوكي المتصفح الذي أنشأ الطلب.
- **أقل بيانات لازمة:** رقم الطلب والتاريخ، خطوات الحالة بأوقاتها، القماش ومبالغه والإجمالي، الشركة ورقم البوليصة، **المدينة فقط** من العنوان. لا هاتف ولا اسم ولا ملاحظات الموظفين.
- الرمز 256-bit، صالح 90 يوماً (المرحلة 4). لا حد معدّل على المسار: التخمين غير ممكن عملياً — مثل `/api/fabric-store/order` القائم.
- **مستقل عن مفتاح الدفع:** إيقاف الدفع الجديد لا يوقف التتبّع ولا التجهيز.

### 2.5 واتساب
زر يفتح `wa.me/<هاتف الزبونة>` برسالة بحسب الحالة (قيد التجهيز / جاهز للاستلام مع عنوان المحل من `store-legal.ts` / شُحن مع الشركة والرقم / تم التسليم) ورابط التتبّع. نفس نمط رسائل التسليم الحالية؛ لا خدمة رسائل.
